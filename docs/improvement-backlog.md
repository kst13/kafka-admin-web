# 관리자 사이트 개선 백로그

2026-08-20 작성. 현재 기능(조회 + 감시 + 토픽 CUD + 그룹 사전 등록 + 파티션별 유입량) 기준으로,
카프카 운영에 효과가 큰 순서로 정리한 제안 목록이다. 항목을 착수할 때는 이 문서를 근거로
설계부터 진행한다.

## 우선순위 요약

| 순위 | 항목 | 효과 | 규모 |
|---|---|---|---|
| 1 | 웹훅 알림 발송 | 감시 체계의 실질적 완성 | 중 |
| 2 | 감사 로그 화면 | 작음 대비 가성비 최고 | 소 |
| 3 | 오프셋 리셋 (조치 실행기) | 가장 자주 쓰는 조치의 UI화 | 중 |
| 4 | 토픽별 디스크 사용량 | 디스크 알림 → 원인 토픽 연결 | 중 |
| 5 | 파티션 쏠림 경고 / 유휴 리포트 | 기존 유입량 데이터 재활용 | 소 |
| 6 | 메시지 조회 강화 | 개발자 문의 대응 속도 | 중 |
| 7 | 홈 대시보드 | 아침 점검 화면 | 중 |

## 1. 알림 발송 (AlertNotifier 웹훅 구현체)

- **현황**: 임계치 초과·수집 실패·인증서 D-30 알림이 H2에 쌓이기만 하고 발송되지 않는다
  (`AlertNotifier` 포트에 `NoopAlertNotifier`만 존재). 화면을 안 보고 있으면 장애를 모른다.
- **제안**: 범용 웹훅(JSON POST) 구현체 1개. URL만 env로 받으면 Slack/Teams/사내 메신저
  대부분을 커버한다.
- **구현 포인트**: 발송 실패가 수집 루프를 깨지 않도록 비동기/예외 격리 필수
  (phase3 착수 문서 B절과 동일).

## 2. 감사 로그 화면

- **현황**: `GET /api/ops/audit-logs` API는 있으나 보는 화면이 없다.
- **제안**: 누가·언제·무엇을(생성/수정/삭제)·결과를 표로 보여주는 화면 하나.
- **구현 포인트**: 기존 AlertsView 패턴 재사용. 반나절 규모.

## 3. 조치 실행기 — 오프셋 리셋부터

- **현황**: 장애 후 재처리, 밀린 랙 스킵 등 운영에서 가장 자주 필요한 조치가
  컨슈머 그룹 오프셋 리셋인데 CLI로만 가능하다.
- **제안**: 기존 ops 모듈 패턴(영향 요약 → 확인 절차 → 감사 로그)에
  `alterConsumerGroupOffsets` 기반 리셋(earliest/latest/특정 오프셋/타임스탬프)을 추가.
- **구현 포인트**: 그룹이 활성 상태면 리셋 불가 → "컨슈머 먼저 중지" 안내 UI 필수.
  이후 파티션 증가(`createPartitions`, 감소 불가 경고), preferred 리더 선출 순으로 확장
  (phase3 착수 문서 A절의 조치 목록 참조).

## 4. 토픽별 디스크 사용량

- **현황**: 브로커 디스크 사용률 알림이 떠도 어느 토픽이 원인인지 알 수 없다.
- **제안**: `describeLogDirs`의 파티션별 로그 크기로 "디스크 상위 토픽 Top 10" 화면과
  토픽 상세의 크기 표시를 추가.
- **구현 포인트**: 이미 있는 토픽 설정 수정(retention.ms)과 바로 연결되어
  "원인 파악 → 조치"가 화면 안에서 끝난다.

## 5. 유입량 데이터 활용 (백엔드 추가 수집 없음)

이번에 추가한 `PRODUCED_PARTITION`/`PRODUCED_TOPIC` 샘플을 재활용한다.

- **파티션 쏠림 경고**: 특정 파티션 유입이 평균의 N배(예: 3배)를 넘으면 파티션 표에
  경고 배지. 프로듀서 키 설계 문제를 조기에 발견한다.
- **유휴 토픽/그룹 리포트**: 7일간 유입 0건인 토픽, 소비 0건인 그룹 목록 — 정리 대상 파악용.

## 6. 메시지 조회 강화

- **현황**: 토픽 상세에서 최신 50건 고정 조회만 가능.
- **제안**: 파티션/오프셋/시간 범위 지정 조회와 키 검색.
- **효과**: "이 주문건이 카프카에 들어왔나?" 같은 개발자 문의 대응이 빨라진다.

## 7. 홈 대시보드

- **제안**: 첫 화면에서 브로커 상태 + 최근 알림 + 랙 상위 그룹 + 유입 상위 토픽을 한눈에.
- **효과**: 아침에 한 번 보는 점검 화면.

## 착수 권장 순서

① 웹훅 알림(운영 커버리지) → ② 감사 로그 화면(빠른 성과) → ③ 오프셋 리셋(조치의 핵심)
→ ④ 토픽별 디스크. ⑤의 파티션 쏠림 경고는 유입량 기능의 자연스러운 확장이라
다른 작업에 끼워 넣기 좋다.

- **사이트 계정 네비 복원**: 사이트 계정 관리(`/users`, `UsersView`) 작업이 머지되면
  `App.vue` 에서 뺐던 `/users` 링크를 "사이트 계정"이라는 이름으로 복원한다
  (기존 "계정 관리"에서 이름 변경), "Kafka 계정" 링크 옆에 배치.
